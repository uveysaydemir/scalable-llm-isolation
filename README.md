# Scalable LLM Isolation — Edge Memory System

A distributed LLM inference system with per-user short-term and long-term memory, and seamless session handover across edge nodes.

---

## Architecture

```
    ┌────────────────┐     ┌───────────────────┐
    │ edge-node-left │     │  edge-node-right  │   FastAPI · Python 3.11
    │   :8080        │     │   :8083           │   Async · httpx
    └───────┬────────┘     └────────┬──────────┘
            │                       │
            └──────────┬────────────┘
                       │
             ┌─────────▼─────────┐
             │   memory-layer    │   FastAPI · Python 3.11
             │      :8090        │   Qdrant client · httpx
             └─────────┬─────────┘
                       │
              ┌────────▼────────┐
              │     Qdrant      │   Vector database
              │     :6333       │   Cosine similarity search
              └─────────────────┘

     All services call native Ollama on the host:
     host.docker.internal:11434  (Metal GPU on M1/M2)
```

## Services

### edge-node (×2)

FastAPI service handling user inference requests, session memory, and handover logic.

- **Inference** — calls Ollama `/api/chat` with streaming (`qwen2.5:7b`)
- **STM (Short-Term Memory)** — in-process session store with configurable TTL; holds the full conversation history for the active session
- **LTM retrieval** — fetches all user facts from the memory layer, embeds with `nomic-embed-text` via Ollama, ranks by cosine similarity to the current prompt using numpy; results are cached in `LTMCache` to avoid repeated Qdrant round-trips
- **LTM persistence** — fires only at TTL expiry (`_flush_expired_stm_loop`) and explicit `/session/end`; loads existing LTM facts, merges with the expired STM via `qwen2.5:7b`, then atomically replaces all facts in Qdrant via `/memory/replace`
- **SSE** — `/events` endpoint broadcasts `persistence_completed` / `persistence_failed` events to any connected client in real time
- **Handover** — predictive mobility handover: packages STM + LTM and pushes to the neighbour edge node before the client disconnects

### memory-layer

FastAPI service wrapping Qdrant for long-term user memory.

- **`/memory/search`** — vector similarity search for a given user + query
- **`/memory/all`** — returns all stored facts for a user
- **`/memory/add`** — embeds and inserts new facts (append)
- **`/memory/replace`** — atomically deletes all existing facts for a user and inserts the new merged set; used exclusively by the LTM flush path

Embeddings are generated by calling Ollama's `nomic-embed-text` model (`768-dim`, cosine distance).

---

## Memory Flow

### Short-Term Memory (STM)

- Created on first request for a `sessionId`
- Appended to on every `generate` call (`user` + `assistant` turns)
- Expires after `SESSION_TTL_SECONDS` (default 120s)
- On expiry or `/session/end`: triggers LTM persistence, then deleted

### Long-Term Memory (LTM) — Merge-and-Replace

At flush time the system:

1. Loads all existing LTM facts for the user from Qdrant
2. Passes them alongside the expired STM conversation to `qwen2.5:7b` with a merge prompt
3. The model produces a reconciled, deduplicated fact list — stale facts overwritten, new facts added, unchanged facts carried over
4. All previous facts are deleted from Qdrant and replaced with the merged set atomically

This prevents accumulation of contradictory facts (e.g. both "Jack is a teacher" and "Jack is an engineer" persisting simultaneously).

**Fact format:** `category: value` (e.g. `name: Jack`, `goals: become an engineer`). Lines with value `unknown` are filtered before writing.

## Technology Stack

| Layer | Technology |
|---|---|
| Inference + fact extraction | Ollama `qwen2.5:7b` — native macOS, Metal GPU |
| Embeddings | Ollama `nomic-embed-text` — 768-dim cosine |
| Vector store | Qdrant |
| Edge API | FastAPI, Python 3.11, httpx (async) |
| Memory API | FastAPI, Python 3.11, httpx, qdrant-client |
| Local similarity ranking | numpy dot-product over cached embedding matrix |
| Containerisation | Docker Compose (edge nodes + Qdrant + memory layer) |

## Configuration

All configuration is via `.env` at the project root:

```env
# Session / cache TTLs
SESSION_TTL_SECONDS=120
LTM_CACHE_TTL_SECONDS=120
MEMORY_SEARCH_LIMIT=5

# Ollama — runs natively on macOS for Metal GPU access
OLLAMA_BASE_URL=http://host.docker.internal:11434
OLLAMA_LLM_MODEL=qwen2.5:7b
OLLAMA_EMBED_MODEL=nomic-embed-text

# Qdrant
QDRANT_HOST=qdrant
QDRANT_PORT=6333
QDRANT_COLLECTION=edge_memory

# Internal URLs (set per-service in docker-compose.yml)
MEMORY_LAYER_URL=http://memory-layer:8090
```

## Prerequisites

- **Docker Desktop** (for edge nodes, memory layer, Qdrant)
- **Ollama** macOS app — install from [ollama.com](https://ollama.com/download), then:

```bash
# Make Ollama accessible from Docker containers
launchctl setenv OLLAMA_HOST "0.0.0.0"
# Restart the Ollama app from the menu bar after running the above

# Pull required models
/Applications/Ollama.app/Contents/Resources/ollama pull qwen2.5:7b
/Applications/Ollama.app/Contents/Resources/ollama pull nomic-embed-text
```

## Demo Dashboard

> The dashboard is a development tool for visualising system behaviour — it is not part of the core architecture.

A React + Vite frontend (`dashboard/`) that connects to the edge nodes for demonstration purposes:

- Polls `/status` on both edge nodes to display live STM/LTM state per user
- Subscribes to both `/events` SSE streams; shows real-time notifications when a session is flushed to LTM
- Filters out `category: unknown` LTM entries client-side so only known facts are shown
- Vite dev proxy strips `accept-encoding` on SSE routes to prevent compression buffering

```bash
cd dashboard && npm install && npm run dev
# available at http://localhost:5173
```
